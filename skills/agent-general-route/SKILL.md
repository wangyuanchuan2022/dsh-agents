# 通用路由（agent-general-route）

> 一句话：流水线选不出来的活，这里接住——**先判要不要拆席，再判给什么人格，最后给谁单干**。

## 0. 何时用 / 何时跳过

- `agent-workflow-router` 的意图表**逐条对不上**，或对上了但硬门过不去（例如活太杂、同时含创作+调研+清理）→ 用本技能。
- 用户**直接点了别的技能名** → 跳过本技能，走那个技能。
- 用户说「你看着办 / 直接干 / 别搞那么重」→ 本技能默认走**单干通道**，除非体量大到主会话装不下。
- 本技能**不做需求访谈、不做计划审批、不做评审裁决**——那些有专门技能，本技能只做「派不派 / 派什么人格 / 谁单干」的裁决与最小执行协议。

## 1. 第一裁决：派席 or 主会话单干（四轴判据）

逐轴打标（真/假），**不做心算凭感觉**，判据写在任务书或本轮记录里：

| 轴 | 判据 | 取真信号 |
|---|---|---|
| **体量** | 单会话能否在合理回合内做完 | 跨 ≥3 个文件、需读 >200KB 上游材料、产物 >20KB |
| **并行** | 能否切成互不干扰的独立面 | 有 2 个以上可同时开工且不碰同一文件的子任务；或同一主题的多种风格/多方案候选 |
| **上下文** | 所需材料是否超出主会话余量 | 需要大量翻旧会话/旧文件而主会话上下文已过半 |
| **风险** | 是否触碰不可逆或安全面 | 动公共 API、schema、发布、凭据、删数据、装依赖 |

**缺省决策表**（按此顺序判，命中即停）：

1. **风险轴为真** → 必须派席：至少配一席只读评审/审计角色，主会话保留执行权。
2. **并行轴为真** → 派席，按可并行面切席（错峰 15 秒开席）。
3. **上下文轴为真** → 派席，把重读/重扫整块外包，主会话只接结论。
4. **仅体量轴为真且超出单席容量** → 派席（拆成多席或分阶段 wake 同一席），否则主会话硬扛。
5. **四轴皆假**（≈15 分钟内、单文件小改、上下文已有）→ **主会话单干，不派**。派席的错峰、回收、唤醒预算成本高于收益。
6. **用户已明确「别派 / 你一个人做」** → 单干，无条件覆盖 1-4。
7. **用户在休息时段（23:00–07:00）** → 按本表自主落定，不发起问询，把裁决写进当轮记录。

**派席数上限**：单轮默认 ≤3 席（错峰启动）；更多先跑完一轮再补派，不堆着。

## 2. 第二裁决：persona 通道（双通道）

| 通道 | 何时用 | 怎么派 | 模型口径 |
|---|---|---|---|
| **A 角色库** | 活需要**成体系的方法论**（勘察/规划/评审/取证/安全审计/缺陷追根/结构提取），且角色库有对口角色 | `agent_taskbook(role=…)` 审稿 → `agent_spawn(role=…, task=…, evidencePath=…, organizer=…)` | 走档位路由表；**先跑 `agent_roles action=tiers` 读当次解析，禁止越档显式指定** |
| **B 临时 persona** | 纯执行 / 创作 / 一次性活（画图、写稿、跑脚本、批量处理、只读勘察某个具体文件、格式转换） | `de_session spawn` + 在 prompt 里现写人格（职责/边界/输入/输出格式/完成判据） | **继承发起会话的 provider/model**（会话树覆盖规则优先；判定生效模型只认 `de_session action=me` 与 spawn 回显） |
| **C 不分配** | 第 1 节判定为单干 | 不 spawn | 主会话自己跑第 5 节协议 |

- 角色 id 与档位**以 `agent_roles action=list / tiers` 当次回显为准**，本技能不复述角色清单（避免文档漂移）。
- 通道 B 的临时 persona 模板见下节，照填即可。
- **不要为了「显得规范」把纯执行活塞进角色库**：角色库带方法论与任务书模板，执行类活只会被模板淹没还多烧一份注入。

## 3. 通道 B 临时 persona 模板（现写即可用）

```
你是【角色名】。职责：<一句话，只写这一件>。
输入：<文件/目录/素材路径，相对工作区表达>。
边界：<禁改哪些文件 / 禁装依赖 / 禁外发>；不写与本职责无关的东西。
输出：落盘到 <相对路径>（先写骨架再分段追加），完成后向组织者会话 <ORG ID> 点对点回报一句结论。
完成判据：<可机检的一条，如「文件存在且断言全绿」>。
在完成判据满足前不要停止工作回合。
```

- 人格只写**这一件**——临时 persona 不写角色卡那么长。
- **ORG 会话 ID 必须预写进 prompt**：子会话反查创建者不可得，没有 ID 就会退化成群发（会唤醒无关会话）。
- 首步只做一件（约 N 分钟，做完立刻落盘），其余降为清单——长工单实测诱发「应酬式结束回合」：零产物转 idle、wake 回执却完全正常。

## 4. 通道 A 派席执行协议

在 `agent-workflow-router` 的派活协议之上，本技能追加/强调：

1. **派前报备**：用户在场时，先一句话报「打算派 N 席：角色/临时人格各做什么」，获批准再开席（用户老规矩：分配人员前须确认）。用户已给出明确分工指令、或处于休息时段 → 视为已批准，直接开并在汇报里注明。
2. **档位现场确认**：每次开席前 `agent_roles action=tiers`，禁越档。
3. **模型不靠漏参**：`agent_spawn` 漏传 model/provider 会**静默**回落到角色档位默认模型，不报错。
4. **报告类必传 `evidencePath`**：只写在 task/deliverable 文本里不保证采用，漏传会落到默认 agent-out 路径。
5. **错峰 15 秒开席**，同一瞬间不开三席。
6. **回收双查**：`de_session action=status` 看 running **加** 目标产出文件 mtime/体积增长；完成广播只证送达不证开工。假 idle（零产出转 idle）→ 补发含硬条款的开工指令并再次确认 running。
7. **成本闸**：凡要新开大量消耗 API 额度的活（批量跑、扩样实验、多席并行），全量跑前先出成本核算书（单价 × 基数）报用户确认；小样本冒烟先跑。
8. **会话留存**：完成的子会话不终止，保留上下文供追加与事后问根因。

## 5. 通道 C 主会话单干协议

单干不等于降标准，最小四件套：

1. **先读实际文件**（改前必重读全文或 diff，不凭记忆构造替换串——文件可能已被用户或别的会话改过）。
2. **增量落盘**：先落骨架再分段追加，长产物别攒一整轮再写。
3. **收尾走格式/验证闸**：交付前按类型跑 `format_gate` / `verification-loop` / 真实输入全量跑；测试类还要看覆盖口径，不认「全绿」。
4. **汇报口径**：结论先行 + 证据路径 + 未证项如实标注；不把过程稿、废弃版本塞给用户。

## 6. 汇报口径：路由决议五行

每次走通用路由，产出一段不超过 5 行的裁决记录（贴在当轮回复或任务书开头）：

```
路由：流水线未命中（<为什么对不上>）→ 通用路由
裁决：<派 N 席 / 主会话单干>，依据 <四轴里取真的那几条>
人格：<通道 A 角色 X（档位 HIGH=…） / 通道 B 临时 persona「…」，继承模型 … / 不分配>
执行：<第一步只做的那件事 + 落盘路径>
收尾：<验收判据 + 回收方式>
```

## 7. 自限条款：何时该退回流水线

通用路由最容易变成「什么都干的黑洞」。出现以下信号，**当场退回对应技能**，并在汇报里说明退回理由：

| 运行中出现的信号 | 退回 |
|---|---|
| 发现是完整特性开发（多文件 + 验收标准 + 新依赖） | `agent-feature`（需求更模糊则 `agent-autopilot`） |
| 发现是缺陷追根（现象不稳、需竞争假设） | `agent-bugfix` |
| 发现要出重大方案且不可逆 | `consensus-plan`（先过用户批准） |
| 变成跨多回合的长跑 | `agent-loop`（先定 max-runs / max-cost / max-duration / completion-signal 至少其一） |
| 变成多方向评审 | `agent-review-squad` |
| 需求本身还说不清 | `requirement-interview`（含糊度门控） |

- 退回不是失败，是把活交回更合适的流程；**已派的席要么收完要么明确停掉**，不悬着。
- 单次通用路由连续退回两次 → 直接问用户要哪条路，别自己猜第三次。

## 8. 反模式（本机已踩）

- **反射缺失**：凭上一轮印象断言「库里没这个技能」——技能目录每轮注入，判定前先看当轮目录。
- **一律派席**：小事也开席、错峰、回收、烧唤醒预算，收益为负。
- **一律单干**：材料超上下文还硬扛，越读越糊直到压缩丢判断。
- **长工单当第一条**：六大段待办的工单实测两次应酬式结束（零产物、无广播）；改「第一步只做一件」立刻开工。
- **只信广播**：完成消息到了就当活干完了——必须 status + 磁盘双查。
- **群发汇报**：`project:` 伪接收者会唤醒目录下全部 idle 会话，消耗唤醒预算；一律点对点直投 ORG ID。
- **信界面标注判模型**：界面 `[model changed: …]` 标注与注册模型可能不一致，只认 `de_session action=me` 与 spawn 回显。
- **门线恒绿**：判据若在坏输入下不红，就等于没有防线——写完判据先造坏样本验证它会红。

## 9. 自检（收工前回看）

- [ ] 路由表真的逐条对不上才进本技能（不是跳过思考的借口）？
- [ ] 四轴判据写下来了，还是凭感觉判的？
- [ ] 派席的话：档位现场确认过？没越档？没靠漏参继承模型？
- [ ] 任务书/临时 persona 含四条硬条款（落盘+点对点回报双条件、增量落盘、不停回合、ORG ID）？
- [ ] 报告类传了 `evidencePath`？开席前向用户报备过（或已获批准/休息时段）？
- [ ] 回收做了 status + 磁盘双查？
- [ ] 命中第 7 节信号了吗？该退回的退回了？
- [ ] 经验值得沉淀吗？→ `skill-eval` 四态裁决（Save/Improve/Absorb/Drop）后再 `skill_manage create`

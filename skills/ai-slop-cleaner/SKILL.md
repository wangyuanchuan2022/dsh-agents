# AI 屎山清理（ai-slop-cleaner）

> 全量移植自 OMC ai-slop-cleaner v5.4.0（145 行）。OMC 设施映射：测试/质量门命令按本机实际工具链跑（node 直跑文件方式）；Ralph 集成 → DSH goal 循环收尾清理。

## 用途
对「能跑但感觉臃肿、重复、测试弱、过度抽象」的代码做有界清理：不漂移范围、不改变预期行为。`--review` 提供仅评审模式。

## 何时用
- 用户明说 `deslop`、`anti-slop`、`去 slop`、`太臃肿`
- 请求是清理/重构感觉噪声大、重复、过度抽象的代码
- 后续实现留下了重复逻辑、死代码、包装层、边界泄漏或弱回归覆盖
- 用户要 `--review` 的仅评审反 slop 遍
- 目标是简化清理，不是新功能交付

## 何时不用
- 任务主要是新功能或产品变更
- 用户要大重设计而非增量清理
- 是无简化/反 slop 意图的普通重构
- 行为太说不清、测试或具体验证计划锁不住

## 执行姿态
- 保持行为不变，除非用户明确要求改行为。
- **先锁行为**：可行时先用聚焦的回归测试锁住。
- **动代码前先写清理计划**。
- 删除优先于新增。
- 复用既有工具与模式优先于引入新写法。
- 不新增依赖，除非用户明确要求。
- diff 保持小、可逆、只对准一种味道。
- 保持简洁与证据密集：检查、编辑、验证、报告。
- 把用户新指令当作局部范围更新，不丢弃此前不冲突的约束。

## 文件清单范围用法
可被限定到显式文件列表或「已改动文件」范围：
- 合适：`ai-slop-cleaner skills/ralph/SKILL.md skills/ai-slop-cleaner/SKILL.md`
- 合适：goal/ralph 会话把本次改动的文件交给清理
- 短文件清单也保持同一回归安全流程
- **不悄悄把改动范围扩成更大清理**，除非用户明确要求

## goal/ralph 集成（DSH：goal 循环收尾清理）
goal 循环可把本技能作为有界的评审后清理遍：
- 标准模式（非 --review）
- 清理范围 = 该会话改动文件
- 清理后回 goal 循环重跑回归验证再完成
- `--review` 仍只是评审后随模式，不是默认集成路径

## 评审模式（--review）
为反 slop 工作保留显式 writer/reviewer 分离：
- **writer 遍**：在测试锁行为的前提下做清理改动
- **reviewer 遍**：检查清理计划、改动文件与验证证据
- 同一遍**不得**既写又自批高影响清理

评审模式下：
1. **不要**一上来改文件
2. 检查清理计划、改动文件、回归覆盖
3. 专项检查：
 - 残留死代码或未用导出
 - 该合并未合并的重复逻辑
 - 仍模糊边界的无谓包装/抽象
 - 缺失测试或被保护行为的弱验证
 - 看似无意实则变味的清理
4. 产出 reviewer verdict 与必须跟进项
5. 需要改的交回**独立的 writer 遍**，不得一步改完自批

## 工作流
### 1. 先保护当前行为
- 明确什么必须保持不变
- 编辑前加/跑最窄的回归测试
- 测试先行做不到 → 动代码前显式记下验证计划

### 2. 动代码前写清理计划
- 把本次限定在请求的文件或功能域
- 列出要移除的具体味道
- 按「最安全删除 → 较险合并」排序

### 3. 编辑前先分类 slop
- **重复**：重复逻辑、复制粘贴分支、冗余 helper
- **死代码**：未用代码、不可达分支、过期开关、调试残留
- **无谓抽象**：直通包装、投机性间接、单用 helper 层
- **边界违例**：隐藏耦合、职责错位、错层 import 或副作用
- **缺测试**：行为没锁、弱回归覆盖、边界用例缺口
- **UI/设计默认**：让 AI 界面显得没被审过的通用视觉模式

### UI/设计评审清单（是评审提示，不是禁令；有明确品牌/可访问性/产品密度/设计系统理由的选择保留）
- **可读性**：正文 11-12px 要质疑；中文/韩文正文一般至少 14px，除非有经验证的密排数据例外
- **阴影克制**：每个面/卡片/图标都投影要质疑；阴影只留真正澄清层级或交互的地方
- **内容层级**：标题已表意就别再塞 eyebrow/标题/描述/多余 `<p>`；避免非产品声音的通用 emoji 徽章
- **配色理由**：无品牌/系统理由时挑战默认 AI 蓝/紫（Tailwind 系 `#3B82F6`）
- **布局节奏**：避免过度完美的 3/4 列均匀网格；产品语境受益于节奏、强调、不对称、轮播/bento、卡片权重变化
- **渐变克制**：非品牌视觉语言时收敛极端渐变

### 4. 一次只跑一种味道的遍
- Pass 1 死代码删除
- Pass 2 重复合并
- Pass 3 命名与错误处理清理
- Pass 4 测试补强
- 每遍后重跑针对性验证；**不得**把无关重构混进同一批编辑

### 5. 过质量门
- 回归测试保持绿
- 对触及区域跑可用的 lint、typecheck、单测/集成测试
- 有静态/安全检查就跑（本机：新增依赖必过 security_review）
- **门失败时：修掉问题，或回退有风险的清理——不硬闯**

### 6. 证据密集报告收尾
必报四项：
- **改动文件**
- **简化点**
- **行为锁定 / 验证运行**
- **残留风险**

## 用法
- `ai-slop-cleaner <target>`
- `ai-slop-cleaner <target> --review`
- `ai-slop-cleaner <file-a> <file-b> <file-c>`
- goal/ralph 循环内：只对该会话改动文件跑清理，然后回循环做清理后回归验证

## 合适度
- **好**：「deslop 这个模块：包装层太多、helper 重复、还有死代码」
- **好**：「清理 src/auth 的 AI 屎并收紧边界，不改行为」
- **坏**：「重构 auth 以支持 SSO」（那是功能变更）
- **坏**：「清理格式」（那是格式化，不是反 slop）

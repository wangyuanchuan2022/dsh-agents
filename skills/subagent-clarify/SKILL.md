# 子会话澄清协议（subagent-clarify）

移植自 MACAE 的工具级 HITL（request_user_clarification + 答案经工具返回值回流）与 OMC 的 AskUserQuestion failure-mode guard，用 DSH 广播原语实现同构能力。

## 何时启用

- 任务书写明 `澄清模式: interactive`；
- 或子会话执行中发现**任务书未给、上下文没有、缺省决策表没覆盖**的必填参数。

不启用：任务书为 `autonomous` 模式 → 一律用缺省决策表，禁止提问（只在产出中标注「该字段为默认值 X」）。

## 五步链路

1. **子会话自查**：动手前清点必填参数。缺任一 → 进入本协议，**禁止**编造、占位符、猜值。
2. **结构化提问**：子会话 `de_broadcast(action=send, recipients=[主会话ID], wake:true)`，格式：
   ```
   【澄清请求】任务：<任务名>
   1. <参数名>：候选 A / B / C —— 各自影响：<一句话>
   2. <参数名>：自由输入 —— 影响：<一句话>
   请 ask_user 后把答案回传；<N> 分钟未回我将按缺省决策表执行并标注。
   ```
3. **主会话转发**：收到后 `ask_user_question` 问真人（问题含候选项与影响说明），拿到答案后 `de_session wake` 或 `de_broadcast(wake:true)` 回传给子会话。
4. **子会话续跑**：答案只用于本任务；已在对话中答过的不重问。
5. **超时降级**：超过任务书规定时限（缺省 5 分钟）无回音 → 按任务书「缺省决策表」执行，产出中显式标注哪些字段用了默认值；主会话下次心跳巡检时顺带核对该标注。

## 防编造条款（每个 interactive 子会话必须遵守）

1. 绝不编造：工具需要的参数没有就必须问，禁止发明值。
2. 先集齐再执行：动手前核对所有必填参数，缺一个就先发澄清请求。
3. 提供选项：有可选步骤或可覆盖默认值时，把选项写进澄清请求让用户拍板。
4. 拿到真实答案才继续。
5. 必须经协议提问，不得只在正文里说「我需要 XX」——主会话看不到未落盘的上下文。
6. 已回答过的不重复问。

## 与心跳机制的配合

主会话心跳巡检清单加一项：核对有无**已发出未回应**的【澄清请求】；有则优先转发 ask_user 或确认降级。子会话死亡断链时，主会话按缺省决策表接管补位。

## 反例（不允许）

- ❌ 子会话编造用户邮箱/日期/金额继续执行
- ❌ 广播不带 `wake:true`（消息停收件箱，等于没问）
- ❌ 主会话收到澄清请求后自己猜答案回传（必须问真人，除非缺省决策表已覆盖）
- ❌ autonomous 模式下发澄清请求（应走缺省决策表）

## 投递纪律（全局，2026-09-19 用户钉死）

- 子会话/评审员的完成与状态汇报一律**点对点直投**组织者会话 ID（任务书必须预写 ORG 会话 ID）；
- **严禁群发**：禁用 `project:` 伪接收者与多收件人广播——该形态会唤醒目录下全部 idle 会话，消耗各会话唤醒预算；
- **每条消息只允许唤醒一个会话**；有 ORG ID 时一律直投，仅在 ID 确实不可得时降级为其他形态，且降级须在汇报中注明；
- 需多方知晓的信息由组织者逐会话转发或汇总说明，执行会话不得代发。
